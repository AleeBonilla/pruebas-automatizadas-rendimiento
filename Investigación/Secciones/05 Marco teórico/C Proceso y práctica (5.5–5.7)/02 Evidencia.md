| E5 | El entorno debe parecerse a producción tanto como sea posible; el rendimiento es una función no lineal del entorno, y cuanto más se aleja de producción, menos fiables son las proyecciones. | «It is important to ensure the test environment is as close to the production environment as possible.» · «It is important to remember that performance is a non-linear function of the environment, so the further the environment is from production standard, the more difficult it becomes to make accurate projections for production performance. | E8 | La línea base es un conjunto de métricas para comparar las mediciones actuales con las anteriores. | «A baseline is a set of metrics used to compare current and previously achieved performance measurements.» | F1 | §4.1.2 «The Performance Test Plan», apartado «Acceptance Criteria», p. 34 |
| E9 | Cuando faltan requisitos no funcionales, el criterio de aceptación suele derivarse del principio de «no peor que antes»: la versión actual debe ser al menos tan buena como la anterior. | «In the case of missing non-functional requirements, the pass/fail criteria of a load test are usually derived based on the "no-worse-than-before" principle. | E10 | Para obtener resultados estables y reproducibles, conviene aislar el entorno de otras influencias y dedicarlo solo a medir. | «First, aim for stable, reproducible results. | E11 | En un sistema de CI industrial, la peor variación entre ejecuciones era menor del 10 % en la mayoría de las pruebas y llegaba al 20 % o más en algunas. | «Our continuous integration system runs thousands of benchmarks periodically [...] It is inherent to this type of benchmarking that the results contain some level of noise. | E12 | Un conjunto de datos pequeño o de complejidad distinta puede dar resultados engañosos. | «Using a small sample set of data or a sample set with a different data complexity for performance tests can give misleading results, particularly when the production system will use a large set of data.» | F1 | §4.2.8, p. 48 |
| E13 | Las máquinas que generan la carga deben monitorearse, para evitar que una más lenta no sostenga la carga. | «To verify the setup, machines involved in load generation should be monitored too. | E14 | En .NET y Java, los resultados sensatos solo se obtienen tras varios minutos de calentamiento. | «However, in this case beware of any technology that relies on runtime optimizing compilers. | E15 | Conviene comprobar contra un *stub* que la prueba alcanza la tasa necesaria, porque muchas pruebas atribuyen a la aplicación un fallo que es de la propia prueba. | «Whenever you are writing capacity tests, it is important to start by implementing a simple no-op stub of the application, interface, or technology under test so you can show that your test can run at the speeds that it needs to and correctly assert a pass when the other end is doing no work.» · «we have seen many capacity tests asserting that the application fails when in fact it was the test itself that couldn't keep up.» | F2 | Cap. 9, «Using Capacity Test Stubs to Develop Tests», p. 244 |
| E16 | No debe emprenderse una prueba de rendimiento sin entender antes qué mediciones y métricas hacen falta. | «Performance testing should not be undertaken without first understanding which measurements and metrics are needed.» | F1 | §2.1.1 «Why Performance Metrics are Needed», p. 17 |
| E17 | Un requisito como «lo más rápido posible» no pone límite al esfuerzo. | «It is not enough to say that your requirement for response time is "as fast as possible." | E18 | En un entorno compartido, una versión puede fallar porque otras pruebas automatizadas corrían a la vez. | «To be really effective, capacity tests need to be run in their own special environment. | E19 | Mucha prueba de capacidad es más medición que prueba: el veredicto depende de un análisis humano que puede ser largo. | «Much capacity testing that we have seen has definitely been more measurement than testing. | E20 | Un SLO es un valor o rango objetivo para un nivel de servicio medido por un SLI. | «An SLO is a service level objective: a target value or range of values for a service level that is measured by an SLI.» | F5 | Apartado «Objectives» |
| E21 | Un SLI es una medida cuantitativa de algún aspecto del nivel de servicio. | «An SLI is a service level indicator—a carefully defined quantitative measure of some aspect of the level of service that is provided.» | F5 | Apartado «Indicators» |
| E22 | Un umbral demasiado exigente produce fallos intermitentes; uno demasiado holgado no detecta un cambio que reduce el *throughput* casi a la mitad. | «On one hand, if you set the level too high, so that your application can only just pass when everything is in its favor, you are likely to suffer regular, intermittent test failures.» · «Conversely, if your test asserts that your application must handle 100 transactions per second (tps) while it can actually handle 200, then your test won't spot introducing a change that almost halves the throughput.» | F2 | Cap. 9, «How Should Success and Failure Be Defined for Capacity Tests?», p. 233 |
| E23 | Proponen subir el umbral de forma progresiva cuando la prueba ya pasa en un nivel mínimo aceptable. | «Next, tune the pass threshold for each test by ratcheting it up once the test is passing at a minimum acceptable level.» | F2 | Cap. 9, p. 233 |

| E25 | La detección de puntos de cambio redujo drásticamente su tasa de falsos positivos. | «The net impact of this work was large for us: Quantitatively, it dramatically dropped our false positive rate for performance changes» | F3 | §8 «Conclusion», p. 75 |
